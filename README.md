# 독도 탐험대 JavaScript 0.4 — 탐험대원 선택과 애니메이션

## 실행

1. ZIP을 먼저 압축 해제합니다.
2. 폴더 안의 `index.html`을 오른쪽 클릭 → 연결 프로그램 → Chrome 또는 Edge로 엽니다.
3. 설치·로그인·서버 없이 플레이합니다. `index.html`, `game.bundle.js`, `style.css`, `assets` 폴더를 함께 유지하세요.

`dokdo-explorers.html`은 코드와 PNG가 모두 들어 있는 단일 실행 파일입니다. 이 파일 하나만 옮겨도 됩니다. 게임은 오프라인으로 동작하며 학습 자료의 외부 출처 링크를 열 때만 인터넷이 필요합니다.

진행은 현재 브라우저에 저장됩니다. 로컬 파일 저장은 브라우저 설정에 따라 달라질 수 있으므로 메뉴 → ‘저장 파일 내려받기’로 백업하세요. 새 버전으로 이동할 때도 저장 JSON을 불러와 이어갈 수 있습니다. 학생 이름 입력, 서버 저장, 학급별 자동 수집은 없습니다.

## 탐험대원 선택

새 모험 시작 → 여학생 또는 남학생 선택 → 확인 → 첫 독도몬 선택 순서로 진행합니다. 첨부한 전신 그림은 선택창에, 4×4 도트 시트는 지도 캐릭터에 적용했습니다. 선택한 카드 아래에서 걷는 모습을 미리 볼 수 있습니다.

선택한 탐험대원은 저장 파일에 함께 기록됩니다. 예전 저장 파일을 불러오면 기존 진행을 보존한 채 처음 한 번 캐릭터를 선택합니다. 메뉴 → 탐험대원 바꾸기로 나중에도 변경할 수 있습니다.

캐릭터는 이동 중 4프레임으로 걸으며, 멈추면 해당 방향의 대기 자세를 표시합니다. 정면 대기 중에는 눈을 깜박입니다. 왼쪽은 오른쪽 프레임을 좌우로 뒤집어 표현합니다. 위로 이동할 때는 제공된 뒷모습 프레임을 사용합니다.

## 문제 전투

- 상대를 만나면 곧바로 첫 문제가 나옵니다. 공격·기술 선택 버튼이 없습니다.
- 내 차례: 정답이면 상대 체력 감소, 오답이면 내 체력 감소.
- 상대 차례: 정답이면 내 체력 유지, 오답이면 내 체력 감소.
- 정답·해설을 확인한 뒤 ‘상대 문제로’ 또는 ‘내 문제로’를 누릅니다. 승패가 날 때까지 문제를 번갈아 풉니다.
- ‘잠깐 쉬기’에서 회복젤, 동료 교체, 교감구를 사용할 수 있습니다. 닫으면 풀던 문제가 그대로 이어집니다.
- 교감구는 야생 독도몬에게만, 한 만남에 한 번 사용할 수 있습니다. 상대 체력이 낮을수록 교감 확률이 높습니다. 첫 새 동료 교감은 성공하도록 설정했습니다.
- 힌트를 본 답변은 도움받은 기록으로 구분합니다. 틀린 개념은 다른 문제 뒤에 다시 만납니다.

## 내 그림으로 바꾸기

**주인공 시트를 바꾼 경우에는 `node build.mjs`를 실행해야 합니다.** 첨부 원본 시트는 `assets/characters/`에 있습니다. 캐릭터 배경 처리가 로컬 파일에서도 작동하도록 코드에 함께 묶기 때문입니다. 전신 그림과 다른 PNG는 아래 방식으로 바꿀 수 있습니다.

가장 간단한 방법은 **`assets` 안의 PNG를 같은 이름으로 덮어쓰고 `index.html`을 새로고침**하는 것입니다. 이미지 수정만으로는 코드를 다시 만들 필요가 없습니다.

| 대상 | 파일 예시 | 권장 크기 |
| --- | --- | --- |
| 독도몬 정면 · 도감 · 지도 · 상대 | `assets/monsters/001.png` | 128×128, 투명 PNG |
| 내 동료의 전투 그림 | `assets/monsters/back/001.png` | 128×128, 투명 PNG |
| 전설의 강치 해랑 | `assets/monsters/100.png`, `assets/monsters/back/100.png` | 128×128, 투명 PNG |
| 여학생/남학생 시트 | `assets/characters/girl-sheet.png`, `boy-sheet.png` | 4열×4행, 한 칸을 32×32로 표시 |
| 선택창 전신 | `assets/characters/girl-portrait.png`, `boy-portrait.png` | 첨부 원본 |
| 각 지역 NPC | `assets/npc/01/01.png` 등 | 64×64, 투명 PNG |
| 건물·나무 | `assets/scenery/` | 기존 PNG와 같은 크기 |

`assets/image-catalog.html`을 열면 파일 이름과 캐릭터 그림을 함께 볼 수 있습니다. `assets/image-list.csv`에는 모든 파일의 이름·용도·크기가 정리되어 있습니다. `assets/monster-contact-sheet.png`는 100종 번호별 미리보기입니다.

그림은 원본 비율을 유지해 가운데에 맞춥니다. 정사각형 투명 배경을 권장합니다. 도트 그림은 32×32에서 그린 뒤 정수 배율로 늘리면 선명합니다. PNG 확장자와 파일 이름의 대소문자를 정확히 유지하세요. 그림이 보이지 않으면 강력 새로고침(Ctrl+F5)을 해 보세요. 파일이 없거나 읽히지 않으면 기존 코드 그림으로 대신 표시합니다.

정면 100장, 전투용 100장, 주인공 8장, NPC 60장, 건물·나무 5장으로 기존 PNG **273장**과 탐험대원 원본 **4장**, 총 **277장**입니다. 기본 전투용 그림은 정면을 좌우로 뒤집은 임시 그림입니다. 직접 그린 뒷모습을 `back` 폴더에 넣어 바꿀 수 있습니다. 지면 타일·기록판·배 등 나머지 지도 요소는 `world.js`에서 그립니다.

`player/`의 이전 8장은 시트 로딩 실패 시 기본 그림으로만 사용합니다. 현재 주인공은 `characters/`의 시트를 사용합니다. 시트 행은 정면 대기 / 정면 걷기 / 오른쪽 걷기 / 뒷모습 순서입니다. NPC 번호 앞 폴더 `01~08`은 지역 번호입니다. NPC 이름은 이미지 목록에서 확인하세요. 건물 그림을 바꾸어도 출입 위치와 충돌 범위는 바뀌지 않습니다.

## 단일 HTML에도 새 그림 반영하기

`dokdo-explorers.html`에는 제작 당시 그림이 포함되어 있어 PNG 파일을 바꾸는 것만으로 갱신되지 않습니다. Node.js가 설치된 컴퓨터에서 이 폴더를 연 뒤 아래 명령을 실행하세요.

```
node build.mjs
```

원본 JS를 고친 경우에도 같은 명령을 실행합니다. `game.bundle.js`와 `dokdo-explorers.html`이 갱신됩니다. 빌드 도구는 별도 npm 설치가 필요 없습니다. 이미 만든 게임을 플레이할 때는 Node.js가 필요 없습니다.

## 주요 소스

- `game.js`: 화면·이동·대화·문제 전투·저장
- `battle-quiz.js`: 복습 문항 선택과 보기 섞기
- `learning.js`: 12개 개념·36개 문항·교육과정 및 자료 출처
- `data.js`: 진화형 포함 100종·8개 지역·NPC 이야기
- `characters.js`: 탐험대원 시트·방향·걷기·눈깜박임
- `player-art.js`: 로컬 실행을 위한 원본 시트 내장 (빌드 시 갱신)
- `assets.js`: PNG 불러오기와 비율 유지
- `sprites.js`: 이미지 누락 시 기본 그림
- `world.js`: 지도·NPC·건물·길 찾기
- `engine.js`: 체력 변화·성장·진화·학습 기록·저장 검증
- `style.css`: 화면과 반응형 배치

소스의 PP·기술 관련 일부 데이터는 이전 저장과의 호환을 위해 남겨 두었지만 문제 전투에서는 사용하지 않습니다.

## 웹에 올리기

`index.html`, `game.bundle.js`, `style.css`, `assets` 폴더를 함께 정적 호스팅에 올리세요. 폴더 구조를 유지해야 직접 만든 이미지가 적용됩니다. 비밀 키나 데이터베이스 설정은 없습니다. 여기서 수정한 파일은 현재 공개 게임 주소에 자동 반영되지 않으므로 변경한 폴더를 다시 게시해야 합니다.

## 검증 범위

엔진 검사, 원본·통합 코드·단일 HTML의 시작부터 엔딩까지의 DOM 진행 검사, 이미지 경로 및 교체 로직 검사를 통과했습니다. 실제 브라우저의 화면 배치와 태블릿 터치 조작은 별도 확인이 필요합니다. 8개 지역은 공통 지도 배치를 사용합니다. 목표 플레이 시간과 수업 효과는 아직 실측하지 않았습니다.

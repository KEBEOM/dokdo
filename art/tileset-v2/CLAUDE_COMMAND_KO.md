# 독도 탐험대 — 기존 배포 게임에 타일셋 v2를 적용하는 Claude Code 명령어

참조 중인 실제 게임: https://dokdo-nu.vercel.app/

```text
너는 현재 제작 중인 웹게임 「독도 탐험대」의 기존 코드를 유지하면서 그래픽만 개선하는 프론트엔드 게임 개발자다.

내가 업로드한 dokdo-game-tileset-v2.zip을 프로젝트에 풀고,
먼저 프로젝트 구조, 실제 2D 렌더러, 타일맵 데이터, 플레이어 이동 로직,
충돌 검사, 저장 방식, 지역 이동, 퀘스트 연결, 3D 보기 진입점을 조사하라.

[절대 보존할 기능]
- CHAPTER 01 동도 선착장 시작 구조와 기존 퀘스트/지역 이름/챕터 순서
- 방향키·WASD 이동, E 대화, 점프, 모바일 조작, 카메라 동작
- 3D 보기, 전체 화면, 소리, 메뉴, 저장 및 이어하기
- 동료/우산몬(0/4), 도감(0/100), 공부 수첩(0/8), 도장(0/8)과 기존 데이터
- 기존 NPC, 대화문, 퀴즈/문제, 이벤트, 엔딩과 로컬 저장 데이터

[리소스 정확한 규칙]
- terrain_32.png: 가로 12칸 × 세로 8칸, 각 32×32px, 총 96개 지형
- objects_32.png: 32의 정수배로 배열된 투명 건물·시설·배·나무·독도등대 등
- details_32.png: 8×4, 각 32×32px, 투명한 거품/이끼/꽃/풀 장식 32종
- characters_64x72.png: 5열 × 6행, 프레임 64×72px, 총 30장
  0행 남학생 아래, 1행 남학생 오른쪽, 2행 남학생 위
  3행 여학생 아래, 4행 여학생 오른쪽, 5행 여학생 위
  프레임 번호는 0~4, 왼쪽 이동은 오른쪽 프레임을 좌우 반전.
- tileset_manifest.json과 character_frames.json을 이미지 좌표의 유일한 기준으로 사용.
- 캐릭터 원본 explorers-atlas-v17.png는 1024×1536이며 여백이 일정하지 않다.
  원본을 32×32 칸으로 잘라서는 안 된다. 정규화된 characters_64x72.png를 사용한다.
- 태극기 이미지는 사용자가 직접 제공한 taegeukgi_exact_reference.png를 기준으로 한다.
  건 ☰ 왼쪽 위, 감 ☵ 오른쪽 위, 리 ☲ 왼쪽 아래, 곤 ☷ 오른쪽 아래.
  작게 보이는 독도 국기는 objects_32.png의 dd_flag로 교체되었으며,
  큰 화면/도감/팝업은 해상도가 높은 원본을 사용한다.

[구현 방법]
1. 기존 2D 맵의 맵 ID·이벤트 좌표·NPC 위치를 우선 유지한다. 새 시범 맵을 바로 기존 씬 전체에 덮어쓰지 마라.
2. 기존 렌더러의 텍스처/아틀라스 로더에 terrain, objects, details, characters를 등록한다.
3. 기존 플레이어 애니메이션을 characters_64x72의 rows/frames에 연결한다.
4. 32px 타일 기준으로 오브젝트를 배치하되 큰 시설은 manifest의 pixel rect 그대로 crop한다.
5. 캐릭터는 발밑 기준(bottom-center)으로 배치한다. 충돌은 전체 스프라이트가 아니라 하단 작은 발판(예: 14×10px)으로 검사한다.
6. 지형 → 데코레이션(충돌 없음) → 오브젝트/캐릭터 Y축 정렬 → UI 순으로 렌더링한다.
7. 이미지 보간은 꺼라: Canvas ctx.imageSmoothingEnabled=false; CSS image-rendering:pixelated;
   WebGL/Three 텍스처 필터는 NearestFilter로 지정한다.
8. 물/절벽 경계, 좁은 길, 계단, 접안시설에서 튀어나오는 프레임이나 막힌 동선을 체크한다.
9. 독도의 실제 지명/시설과 창작 세계를 구분해 표시하고, 설정에서 허가되지 않은 이동 가능 지역을 사실처럼 설명하지 마라.
10. 울릉도 샘플 맵은 이후 확장용으로 두되 기존 CHAPTER 01 시작 위치를 울릉도로 바꾸지 마라.

[검증과 산출]
- demo.html은 제작된 도트 그림을 확인하기 위한 별도 실험용 데모이며 기존 웹게임 코드를 대체하지 않는다.
- 바뀐 소스 파일 목록과 구현한 렌더러 API를 알려줘.
- 기존 저장 데이터 유지 검증, WASD 및 모바일 이동, E 대화, 우산몬·도감 수치 유지,
  새 시작/이어하기, 3D 전환, 지역 이동, 태극기 정확성, 맵 경계와 충돌을 테스트해.
- 기존 기능이 깨지면 그래픽 변환 어댑터를 만들어 해결하되 게임 로직을 새로 만들지 마라.
- 최종적으로 CHAPTER 01 동도 선착장 실제 게임 화면의 수정 전/후 스크린샷을 비교해 보여줘.

이 작업을 수행하기 전 현재 소스가 접근 가능한지 확인하고, 없으면
코드 접근이 필요하다고 알려줘. 배포 URL만 보고 소스 구조를 추측하여 코드를 교체하지 마라.
```

## 중요한 경계
- 이 아카이브의 `map_dokdo_v2.json`과 `map_ulleungdo.json`은 **시연용 창작 맵**이다. 현재 사이트의 맵 데이터를 자동으로 덮어쓰는 파일이 아니다.
- 캐릭터 파일은 사용자 제공 원본을 게임 프레임 규격으로 변환한 것이다.
- 클로드에게 소스 폴더 또는 GitHub 저장소를 제공해야 실제 운영 사이트의 파일을 정확히 고칠 수 있다.
